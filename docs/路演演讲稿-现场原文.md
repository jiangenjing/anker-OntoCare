创新点：
我们今天和业务聊，了解到anker现有的技术架构是workflow，而我们的架构是基于本体论的RAG

1️⃣现有方案痛点：传统的智能客服架构把规则硬编码在代码或流程里，属于“牵一发而动全身”。一旦安克新增了品类、调整了售后政策，底层代码、API 和 Prompt 全都要跟着重写，维护成本极高。
我们的创新（本体论降维打击）：我们彻底摒弃硬编码，采用 Service Ontology + Decision Ontology 双本体路线。将业务实体和售后SOP沉淀为一张可视化的知识图谱。

2️⃣亮点二：基于红蓝对抗降噪与 Badcase 驱动的自进化飞轮
售后场景的“致命伤”是幻觉，传统 RAG 面对复杂多轮对话极易崩溃（多跳能力弱），且无法从错误中学习，而我们的创新（四步自进化闭环）：
- ① 红蓝对抗：用 Persona 模拟不同性格的买家（急躁型、技术型、情绪宣泄型、利益导向型等），与客服 Agent 进行多轮对话
- ② Judge 评估：引入 LLM as a Judge，从事实性、安全性、相关性、合规性等维度打分；同时引入 Supervisor 做裁判，判定不合格的，打上 Bad Case 标签，并找出失败原因。
- ③ 降噪与剔除：针对 Bad Case 进行修正
检索召回了错误知识，就降低其在向量库中的权重或剔除；
知识不够权威，就修正 FAQ 条目；
没有检索到，就把不常见的长尾问题
规则缺失，就更新 Decision Ontology。
- ④ 人工审核回流：修正后的知识必须通过运营人员的人工审核，通过后再写回知识库和 Ontology 中。
🔴产品上线后，用户可以针对回复进行打分，点赞或者点踩，good case或者bad case都会记录进知识库，这样就实现了整个系统的自进化。
✅在我们的测试集上，进化前的8轮内问题解决率仅83%，自进化后的解决率达到98%

3️⃣亮点三：业务经营归因agent
推出面向商家的归因 Agent，处理的是“工单的集合”。它自动将快照数据转化为带责任归属和规则 ID 的决策建议。
这三个创新点强强联合，形成了数据飞轮，最终达到的系统级效果，就是抗幻觉。


抗幻觉方面采用图谱 + 向量检索混合架构：依靠本体图谱完成图推理与业务决策，这是结果的权威来源；向量检索仅作为补充，用于召回 FAQ、SOP 文本素材。最后叠加幻觉检测校验环节，对 Agent 输出的业务结论和工具调用动作做二次拦截校验，多层次抑制大模型幻觉。
