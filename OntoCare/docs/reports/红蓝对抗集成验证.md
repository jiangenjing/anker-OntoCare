# 红蓝对抗集成验证

实现与接口说明见 `docs/evaluation/benchmark/INTEGRATION.md`；Prompt 版本为 `red-blue-1.2`。

## 已落实

- 红队、蓝队、裁判、编排与混沌模块拆分，三类 Prompt 在 config/prompts.py 中真实使用。蓝队调用原客服处理链，缓存、来源引用与 Action Gateway 不被模型 Prompt 绕过。
- POST /api/benchmark/run 返回 202 和运行编号；状态与 Trace 接口可查询。本机独立子进程运行，实测原客服会话保持不变。
- 动态 Persona 首轮逐字来自源表，后续可用 LLM 追问；情绪由代码更新，耐心/轮数限制为最多 8 轮。固定攻击用例继续复用原攻击输入，不伪造真实恶意客户。
- 原理图展示 Prompt 要点、混沌工程和红蓝分工。逐轮抽屉呈现输入、状态变化、实际响应、引用与 Trace、裁判及终态。真实模型分数显示 ESTIMATE；未测字段不填假数。
- 手动“已修复”仅为本浏览器待复测备注，原始结果不变。已归档在线 P01 Trace 内嵌在 HTML，离线也可打开。

## 成绩口径

本次验证证明模块与接口可运行，不是重新完成 74 核心任务 × 8 次的全量在线评测。新动态运行与历史固定脚本不同，结果独立保存，不能混合计算 pass³/pass⁸。P01 在线样本“检查通过”不等于包裹已找回；其目标达成估计和停止原因在 Trace 中单独显示。

同模型独立裁判仍有偏差，分数未经人工校准。Prompt 的事实约束与标识校验不等于完整的语义证明；模型异常/不合格生成保留明确状态。身份核验、真实退款、物流调查执行与实际接通人工仍未实现。
