# 归因 Agent：Plan → Action

需求来源：用户提供的 OntoCare_售后归因Agent（JSON v3）。保留真实LLM和Flask架构，不将已有系统退回单HTML模拟。未核验的商业数字不进入产品。

|步骤|行动|验收|
|---|---|---|
|1|源数据字段审计，工单/订单/Q&A连接及引用|无客户ID、投诉日期、维修成本则显示缺失；不以订单号冒充客户|
|2|RC1–RC4候选规则、错误码及证据抽取|日期、金额、SKU中的数字不当作错误码；标签有rule_id及原文证据，不能强制每单归因|
|3|四个帕累托图、80%线、下钻|分母明确、累计终点100%、下钻工单与计数一致；地区以可识别的订单地址国家作替代并注明|
|4|摘要、证据完整度、FAQ审核草稿、回复版本|真实源字段，未审核内容不自动入正式库；保留每版编辑|
|5|四类报告预览与导出|周报7块；缺时间不能生成真实周环比；订单金额不能算售后成本；仅生成不推送|
|6|回归与交付|Python+前端逻辑测试，页面检查，更新ZIP与逐项状态|

## 数据边界

- RC标签是待核查线索，不是因果结论；未命中可无RC标签。
- D2名单未命中保持UNKNOWN；D5不采用无来源30天退款或过保付费维修。
- F19缺投诉日期不可计算；F20缺退款/换货/维修流水不可计算。
- 国家不唯一对应时区，F14不自动承诺截止时间。
- 数据仅有首封邮件，不虚构情绪历史和处理效率指标。
- 所有新增建议来自本地规则并标注规则编号；知识ID仅在同PN且实际匹配时附上。

## 执行结果

步骤1–5已按上述数据边界落实；步骤6已完成自动化和浏览器核心交互验证。详细功能状态与未实现项见《归因 Agent 本次交付.md》，不宣称20项原样全部实现。
