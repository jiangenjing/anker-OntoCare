# 用户端与商家端

访问 / 为用户端，/merchant 为商家端。右上角切换视角，统一黑白灰简约样式；桌面侧边显示真实工单改写的提问，小屏自动移到下方。

用户成功完成第 9 次问题提交后显示“联系人工”和“转邮件处理”。计数由后端维护。请求保存在 data/handoffs，商家待处理列表可读；重复提交同一渠道返回原记录。人工尚未接通，邮件尚未发送。两端切换后可恢复本服务运行期间的会话与引用；服务重启会清空活动对话，但已经转入的记录保留。

商家点击“查看邮件”显示产品、SKU、订单号和来源。原表没有客户 ID、客户邮箱，明确显示未提供；会话 ID 单独标明，不能当作客户 ID。修改邮件后隐藏旧信息，避免错用来源。对话转入保留完整记录，以最近实质问题和最新反馈继续生成。

一键生成沿用本体对象与规则判断、公开来源、FAQ 缓存和长尾模型辅助机制，保留流式进度与引用。当前未配置真实 LLM，实际使用规则与资料，界面不会宣称模型已调用。模型配置沿用 LLM_BASE_URL、LLM_API_KEY、LLM_MODEL；密钥仅由服务端读取，不放入 HTML。

58 项测试通过，覆盖第 8/9 次边界、转接去重、人工等待状态、独立会话、引用和原邮件流程。浏览器验证双视角、基础资料卡、一键生成、第 9 次入口。发现并修复“只收到配件，扫地机还没到”的物流意图识别遗漏。

HTML 文件位于 static/index.html、static/merchant.html；共享样式 static/anker.css。直接打开 HTML 只能预览，数据与生成依赖 Python 服务。请运行启动.command 后访问 http://127.0.0.1:5088/ 。本地双端是角色视角切换，不是账户权限隔离，不能直接作为生产邮件系统部署。
