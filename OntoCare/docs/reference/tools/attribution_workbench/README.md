# OntoCare 归因工作台

交付页面：`static/analytics.html`。全部 CSS、JavaScript 和业务数据内联；双击即可使用，不需要 Python、网络或 API Key。运行原项目时访问 `/analytics`。用户端和商家端链接仍需要原项目服务。

重新生成：在项目根目录执行 `python3 scripts/attribution_workbench/build.py`。

## 数据范围

仅读取 `evaluation/ontocare-test-suite.json` 和 `knowledge/long_tail/长尾问题_检索策略.json`。

测评集 M007–M009 提供 63 条源表工单行号、问题类型和错误码统计。M009 分布为 52 条排障/使用、11 条物流。原文样本提供 18 条邮件正文、10 条明确产品名称；产品图为这 10 条记录的 7 个原文名称分组，不代表完整产品分布。缺失详情显示未提供，不能从测评问题生成邮件，也不能把虚构负例加入真实工单。

RC1/RC2/RC4 没有正例证据，显示 0 并解释缺口。RC3 由 M008 的非空错误码行号去重得到 18 条调查候选，不代表产品设计缺陷、事故率或已确认原因。DO-* 为此次新增的前端复核规则标识，关联测评约束，未新增后端退款/换货执行能力。质保状态只展示 M015–M017 指定参考日期的测评期望。

长尾策略是用户提供、未经独立核验的调查建议；不能替代官方政策或订单事实。投诉日期不完整，所以不提供时间筛选或伪造周度趋势。

## 使用

点击 RC 卡片查看定义、缺口、规则与工单；点击横条筛选工单；列表分页每页 8 条。三项核查任务可填写记录、保存为核查中或已核查。记录仅存当前浏览器的 localStorage；受限环境下退回页面内保存并提示导出。点击生成改进报告后分别下载 JSON 和 HTML，两者来自同一快照并包含核查记录。没有真实发信、退款、换货或 LLM 调用。
