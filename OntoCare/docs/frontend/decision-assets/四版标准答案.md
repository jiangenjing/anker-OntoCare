# 归因与决策：四版标准答案

基于当前63条快照，属于预设演示答案，非四次实时模型生成。

## 版本 1

建议把经营重点放在“减少重复客诉、提高处理效率、补齐知识与数据”上。当前优先处理情绪风险，再排查产品与物流体验。

数据范围：当前 63 条工单快照，其中故障 / 使用咨询 52 条，物流咨询 11 条。投诉日期不完整，不能判断“最近增长”；没有销量分母，不计算产品故障率。

1. 情绪风险 · 人工优先复核（P1）
事实：3 条邮件命中明确愤怒/投诉词组，属于待复核线索。
待核查原因：重复故障、连接体验或反复沟通可能影响情绪，需逐条核查。
行动：人工核实语境后安排优先处理，交接附原文和已尝试步骤，比较产品分布。
负责人：客服运营 + 产品团队。验证投诉升级率与人工首次响应时间。
依据：工单第57行、工单第59行、工单第61行；规则 DO-OPS-EMOTION。

2. 重复报错 · 按型号专项核查（P2）
事实：E28 / T2352、E25 / T2353 的 2 条工单均包含 3212 和拖布阻塞描述。
待核查原因：维护步骤、使用环境或个体硬件故障均可能相关；跨型号不能推断同一设计缺陷。
行动：分别核对型号、错误码和已尝试步骤，复现后再决定是否提交工程调查。
负责人：产品团队 + 技术支持。验证重复核查耗时、复开率是否下降。
依据：工单第19行、工单第28行；规则 DO-RC3。

3. 物流拆单 · 逐件展示进度（P2）
事实：11 条物流咨询；其中“主机未收到、只收到配件”等情况需结合订单逐件核对。
待核查原因：拆单展示不清、承运记录滞后或实际未投递均可能造成重复咨询。
行动：在订单页逐件展示包裹与物流状态，补充主机/配件到货核对入口。
负责人：物流运营 + 客服。验证物流重复咨询率与平均处理时长。
依据：工单第2行、工单第3行、工单第4行、工单第5行、工单第6行、工单第7行、工单第8行、工单第9行、工单第10行、工单第11行、工单第48行；规则 DO-OPS-SHIPPING。

4. 知识覆盖 · 核对错误码映射（P2）
事实：1 条工单的展示错误码未匹配同PN公开知识标题；不等于整个Q&A没有答案。
待核查原因：标题索引、内部码与展示码映射或知识内容覆盖可能不足。
行动：先核对内部码与展示码，再审核补充排障条目；保留来源和适用条件。
负责人：知识运营 + 技术支持。验证同型号有效召回率与问题复开率。
依据：工单第14行；规则 DO-OPS-KNOWLEDGE。

5. 质保边界 · 先补齐投诉日期（P2）
事实：4 条具备投诉与质保日期，0 条落入到期后 1–30 天窗口；不能认定临界投诉集中。
待核查原因：保修预期与适用政策可能存在理解差异，当前资料不足以确认。
行动：补齐日期后核查分布；如确有需求，再评估到期提醒与维修说明，不自动延保。
负责人：客服运营 + 产品团队。验证日期完整率、保修重复咨询率；不预估降幅。
依据：工单第30行、工单第39行、工单第54行、工单第56行；规则 DO-OPS-WARRANTY。

6. 高频产品 · 优先安排抽查（P2）
事实：X10 Pro 有 14 条工单，占全量 22.2%；其中包含物流咨询，不等于同一种硬件故障。
待核查原因：销量规模、使用场景、物流或产品问题都可能影响工单量。
行动：按产品和问题类型抽样，核查原文、处理步骤与知识，避免直接以工单量认定质量责任。
负责人：产品运营 + 客服。验证抽查命中率、复盘耗时和知识复用率。
依据：工单第4行、工单第5行、工单第8行、工单第17行、工单第20行、工单第21行、工单第22行、工单第23行、工单第25行、工单第29行、工单第30行、工单第39行、工单第40行、工单第44行；规则 DO-OPS-FOCUS。

经营闭环：业务方提供 SOP、工单、订单、经销商与 Q&A，并明确字段含义 → 标准 Prompt 生成特定业务归因 Skill → 用已核验的 Bad Case 修订 Skill → Agent 关联产品、订单和规则 → 输出事实、假设、责任团队、行动与证据链 → 人工审核 → 回收指标并复盘。

当前不足：投诉时间和部分关联字段不完整；错误码映射与知识标题覆盖需要复核；业务动作执行与效果反馈尚未接入。责任团队是建议承接团队，不代表已认定责任。

先完成证据核查与责任分派，再用同口径指标验证改进；先解决可确认的问题，不把统计相关性当作根因。 所有建议尚未执行；不自动退款、换货或调整质保。
