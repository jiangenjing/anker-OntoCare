## 已落地

- conversation_workflow.py：按会话保存排障步骤、反馈与引用；支持“下一步”“第二步没看懂”“都试过了还是不行”“好了”。下一步不会被记录成成功，最后一步之后会询问结果。
- app.py：接入连续排障；切换型号、订单或明确问题时清除旧流程；EB1L 精确匹配 T2080 和原表第 482 行。
- ontology_catalog.py：检查输入 ZIP 的知识编号和步骤关联；结果保存在 data/ontology-import-audit.json。
- agents/router、workflow、responder、citations 下分别新增 Agent.md。它们描述现有模块的四项职责，并非新增四个独立模型进程；responder/Agent.md 在服务启动时实际加载进回复提示词，其余规则由程序实现。
- 固定答复按型号、主题及来源版本匹配，命中不调用模型。这里是应用层答案缓存，不是模型内部 KV Cache。
- 流式输出展示实际处理状态与处理摘要，引用链接指向原文件、工作表和单元格，不输出内部思维链。

## 验证结果

41 项自动化测试全部通过，覆盖原有数据、物流、话题切换、缓存、来源权限、流式接口和新连续流程。

| 场景 | 结果 |
|---|---|
| 吸奶器弱吸力 → 第二步解释 → 失败 → 下一步 | 保留本案进度和引用，零模型调用 |
| 全部尝试仍失败 → 下一步 | 保持待人工核查，不重新循环步骤 |
| 用户反馈好了 | 记录为用户报告解决，不伪造设备检测结果 |
| 切换型号、转问物流、不同会话 | 不沿用旧排障步骤 |
| 排障中报告身体不适 | 停止原排障流程，进入人工核查回复 |
| EB1L → 下一步 → 最后一步 | 使用同一来源，推进到实际步骤，最后询问结果 |
| 浏览器实际操作 | EB1L 后输入下一步，显示进水口检查及 Sheet1!D482:E482 引用 |
| 正在运行的流式接口 | 返回进度事件及最终答复 |

测试命令：`.venv/bin/python -m unittest discover -s tests -q`。

## 数据与边界

Q&A 共 875 条，公开 872 条。整理出 23 个固定工作流、25 个型号/主题缓存键；没有真实咨询频率，不能据此声称覆盖 80% 的用户问题。
